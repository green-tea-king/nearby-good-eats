# 在地美食榜完整收斂設計

## 目標

把目前已部署但仍有缺口的搜尋、成本、資料、後台與手機體驗收斂成可驗證的正式版。

## 固定決策

1. 關鍵字、地區、評鑑、菜系與營業條件是硬條件；只允許交通距離用同心圓自動放寬。
2. 每次成功搜尋至少顯示 3 張卡片；若硬條件沒有 3 家，顯示實際符合數量與明確的使用者可確認放寬按鈕，不自動塞入不相干店家。
3. 「再找一組」以目前候選池與已顯示 place_id 排除後取下一組，不重複前三名。
4. 預設情境為定位點、走路、營業中；定位權限只在按套用後請求。
5. 全台模式使用批次候選快取，優先使用本地評鑑資料與單次必要 Google 查詢，禁止每次 UI 操作重查。
6. 正式版先使用受 HTTP referrer 與 API 範圍限制的 browser key；Functions、App Check、每日配額設定保持可切換，但不可在未部署時假裝已啟用。
7. AI 只在實際後端回傳 tags/confidence/reason/sources 時顯示；空 endpoint 必須呈現未啟用。
8. 外部評鑑只讀批次資料；正式欄位要驗證年份、來源 URL、地址、行政區與菜系待確認比例。

## 實作邊界

- index.html：搜尋狀態機、放寬、下一組、預設交通、卡片與分享路由。
- assets/app-settings.js、functions/index.js、firestore.rules：API 安全與成本設定。
- admin.html：事件統計與獎項覆蓋欄位映射。
- scripts/：資料完整度、外部來源契約與互動 smoke。
- assets/awards-taiwan.json、assets/external-signals.json：只更新可追溯批次資料。

## 驗證標準

- awards validator 通過，且另外回報地址、行政區、菜系待確認數。
- 外部來源驗證器與目前六類核心資料契約一致並通過。
- 390x844 與 360x800：無橫向溢出、固定登入列不遮卡片、濾網只在套用後搜尋。
- 搜尋零結果、1 筆、2 筆、3 筆與下一組都各有可重跑的回歸測試。
- 正式站版本、登入頁、空白初始狀態、搜尋結果、分享路由與後台統計均完成 smoke。
